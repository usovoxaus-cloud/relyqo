# Структура RELYQO

Рабочая структура существующего приложения FastAPI, сайта и мобильной оболочки. Изменения подготовлены в ветке `codex/relyqo-structure-20260930`.

## 1. Приложение потребителя

| Раздел | Адрес | Назначение |
| --- | --- | --- |
| Найти | `/consumer`, `/nearby` | Узбекистан, область и город, поиск услуги или организации, категории, помощь ИИ, карта по запросу |
| Оценить | `/rate` | Выбор организации для Community-оценки или подтверждение посещения по одноразовому QR |
| Профиль | `/me` | Свои оценки, избранное, фото, обращения и восстановление доступа |

На основных потребительских страницах одно меню из трёх разделов. На небольшом экране оно находится внизу. В мобильной оболочке используется её собственная панель вкладок.

Рейтинг лучших организаций доступен из поиска. Карточка организации, история отдельной оценки и форма Community остаются вложенными страницами.

Существующие ссылки `/?token=…` и `/consumer?token=…` продолжают открывать подтверждение посещения. `/` сохранён как вход для QR и старой версии мобильного приложения.

Подтверждённые посещения (Verified) и Community имеют раздельные оценки и число отзывов. Фото дополняет отзыв. Математический расчёт находится в `app/score.py`; ИИ не выставляет баллы.

## 2. Центр управления

| Раздел | Адрес | Что доступно |
| --- | --- | --- |
| Обзор | `/admin#dashboard` | Состояние платформы, очереди и показатели |
| Организации | `/admin#applications` | Реестр, поиск по названию и городу, филиалы, заявки, публикация и подключение QR |
| Оценки и жалобы | `/admin/control#cases` | Очередь проверки, отзывы, причины, материалы и история решений |
| Аналитика с ИИ | `/admin/analytics` | Сводная статистика, фильтры, рекомендации и переход к задачам улучшений |
| Редактор с ИИ | `/admin/editor` | Черновик, предварительный просмотр, явное сохранение и отмена доступных изменений |
| Реклама | `/admin#ads` | Кампании, медиа, сроки, ограничения и статистика |
| Настройки | `/admin/settings` | Безопасность, роли, языки, категории, состояние системы, резервные копии и журнал |

Единое меню доступно на каждом экране управления. Ссылки на конкретные разделы работают после входа и при возврате кнопкой браузера.

Редактор ограничен текстами главного экрана и категориями. Он не выполняет сгенерированный код и не меняет рейтинги. Проверка спорных оценок требует обоснованного решения; низкая оценка сама по себе не является причиной исключения.

## 3. Кабинет бизнеса и сотрудники

| Экран | Адрес | Доступ |
| --- | --- | --- |
| Кабинет | `/business-owner` | Профиль и QR своей организации |
| Аналитика | `/business` | Показатели и рекомендации для организации вошедшего владельца |
| Сотрудники и журнал | `/owner#staff` | Создание и отключение сотрудников, сброс их паролей, журнал выдачи QR |
| Сотрудник | `/staff` | Выпуск QR своей организации и безопасность своего аккаунта |

Сервер получает организацию из сеанса пользователя. Переданный клиентом чужой идентификатор не переключает аналитику на другую организацию. Сотрудник не получает доступ к аналитике владельца, сотрудникам, профилю или администрированию.

Новая роль сотрудника — `BUSINESS_STAFF`. Существующие аккаунты `FREGAT_OWNER` и `FREGAT_STAFF` поддерживаются без миграции. Именованные старые API Fregat сохранены для совместимости, но общие экраны не зависят от них.

QR выдаётся только активному филиалу организации со статусом `VERIFIED_PARTNER`. Текущая модель связывает аккаунт владельца с одной организацией; выдача выбирает её первый активный филиал. Назначение сотрудника отдельному филиалу не добавлялось.

## 4. Модули программы

| Область | Основные файлы |
| --- | --- |
| Запуск API и существующие маршруты | `app/main.py` |
| Общая оболочка потребителя | `app/web_ui.py`, `app/static/consumer-nav.css` |
| Упрощённый поиск | `app/static/consumer-search.js`, `nearby.js`, `ai-search.js` |
| Общее меню управления | `app/static/management-nav.js`, `management-nav.css` |
| Реестр организаций | `app/admin_directory.py`, `app/static/admin-directory.js` |
| Аналитика одной организации | `app/business.py` |
| Организации и категории | `app/models.py`, `app/categories.py`, маршруты профилей в `app/main.py` |
| География и внешний поиск | `app/geography.py`, `app/uzbekistan.py`, `app/search.py` |
| Посещения, QR, аккаунты | `app/security.py`, `app/models.py`, соответствующие маршруты в `app/main.py` |
| Оценки и расчёт | `app/score.py`, `app/feedback.py` |
| Модерация, уведомления и задачи | `app/feedback.py`, `app/admin_workflow.py` |
| ИИ и сводная аналитика | `app/ai.py`, `app/analytics.py` |
| Редактор | `app/app_editor.py` |
| Восстановление доступа | `app/password_recovery.py` |
| Состояние системы и копии | `app/operations.py`, `app/backups.py`, `app/scheduled_backups.py` |
| Языки | `app/i18n.py`, `app/static/i18n.js`, `i18n-uz.json` |
| Android и iOS | `mobile/`, тот же API и потребительские страницы |

Новые общие компоненты выделены в отдельные модули. Существующие маршруты ещё частично находятся в `main.py`; это постепенное упорядочивание действующей программы, без замены её стека.

## 5. Готовность к запуску

Дополнительные исправления, миграции 0026–0027, правила рейтинга, источники стартового каталога и ограничения описаны в [LAUNCH_READINESS_RU.md](LAUNCH_READINESS_RU.md).

Публикация выполняется через проверку ветки в GitHub Actions и обновление `main`; Render использует существующий автоматический деплой. Видимость сайта и тариф веб-сервиса не изменяются. Перед завершением проверяются работа PostgreSQL, сохранность прежних оценок, открытие потребительских страниц и доступность приватных маршрутов только после входа.
